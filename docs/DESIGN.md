# 设计与边界

## 稳定人设与变化中的记忆

角色 JSON 是稳定配置。模型使用工具更新记忆，但不能通过这些工具导入
任意包、执行脚本、修改角色源码或写任意路径。若需要改人设，编辑角色包，
以新的 ID 导入；v1 不隐式覆盖现有角色。

长期记忆按角色共享；每条带时间、ID、类型，支持修订。
短期摘要按角色+会话存储，带 expiresAt。过期后不注入，但原数据仍在私人
备份中。显式 resume 只接收已存在、同角色会话的未过期摘要。

这提供可检查的外部记忆，不是模型权重训练，也不能保证模型自行记事。

## 存储

一个版本化 state.json 包含角色、记忆与会话绑定。单次修改在独占写锁下
重新读取最新状态，验证后写临时文件，再通过 rename 提交。
失败不得用默认样例覆盖已有损坏文件。目录不允许经过符号链接或 junction，
导入内容不含路径，也从不 eval。JSON 有大小、条目和字符串上限。

多进程冲突返回 BUSY，不静默丢失写入，不自动“抢走”旧锁。若发生断电：
先退出所有使用相同 home 的实例，备份整个 home，确认没有存活写入者，
再人工检查并处理残留锁和临时文件。不要在活跃进程写入时清锁。
这不是加密数据库，也不抵抗同一 OS 用户恶意替换目录的竞态攻击。

## 上限

- 32 个角色、200 个会话绑定，总 state 上限 2 MiB。
- 每角色 200 条长期记忆，每条正文 2000 字符。
- 短期摘要 4000 字符，有效期1–720小时。
- 角色主设定12000字符，名称80字符，其余文本字段各4000字符。
- 默认上下文只返回最近30条长期条目；关键词检索最多20条。

达到上限时报错，不悄悄删记忆。v1 无自动删除或无限增长能力；
较长历史需要用户备份后显式重新组织成新的角色包/存储。

## 公开导出与私人备份

公开包按白名单投影角色字段，不带长期或短期记忆。
私人包明确标记 private:true，导入也需显式 includeMemory。
这防止结构性误分享，不会识别用户写在人设正文里的个人资料。
公开发布前仍应预览角色内容。

## Harness 适配

每次 prompt assembly 按 assembly.agent.session.id 解析绑定与当前状态。
无会话和子代理默认不注入；工具也拒绝缺失身份或子代理访问。
第一次读取会话时固定绑定默认角色，之后全局默认角色的更改不影响它。

插件工具需宿主 SDK，核心不需要。宿主的 API 变更可能导致插件注册失败，
因此兼容声明固定在目标版本。模拟宿主测试不代表真实桌面端已验证。

## 主动聊天运行时

src/idle.js 维护 live agent 订阅并每15秒发现已保存会话；src/idle-store.js 独立保存启用设置、计数与错误暂停。单个 unref 计时器每15秒检查；
单调时钟控制等待与冷却，本地墙钟只判断安静时段。恢复时重等完整间隔，沿用未回应计数。原 state.json 无格式迁移；idle-consents.json 使用锁、原子替换、授权 token 与 revision 检查，派发前保存配额。
消息携带独立 UUID 和 dsh-assist-idle 来源，通过原 agent.followup 提交。
计时器在 agents.withoutInitiator 中创建，避免继承启用工具的 agent 归因。
派发前复核 agent 对象身份、状态、输入队列和上限；先预留次数再调用，
重入时不重复提交。旧调用失败不能禁用刚重新启用的新订阅。
工具入口只允许当前 live 主会话；start 需要最近 user-role 消息来自真正用户，
拒绝主动触发回合自己续订。是否用户明确要求启用还需模型遵从工具说明。
stop 删除保存的授权；卸载清理监听器/计时器但保留设置，不取消已提交宿主工作。详细行为见 [IDLE.md](IDLE.md)。

## 不自动做的事

没有关机唤醒、外部聊天平台、X 发帖、系统安装、远程同步、
凭据管理、模型余额查询或自动 GitHub 发布。
这些功能需要独立适配与明确授权，不应混在人设包文本中暗中启动。
