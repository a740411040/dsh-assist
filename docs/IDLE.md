# 无人回复时主动聊天

v0.2.0 增加了真实的宿主唤醒逻辑：插件计时，到期后向同一 live agent 调用
`followup()`，由原会话的模型使用当前人设和记忆生成回复。不是预先写死的聊天文本。

## 下载者如何启用

按 [桌面端安装说明](DESKTOP.md)安装本项目或 v0.2.2 TGZ。
只读取 SKILL.md、导入角色 JSON 或运行 CLI 不会启动主动聊天。

在希望陪聊的会话发送：

> 使用大肥鱼女儿角色。开启主动聊天：我 15 分钟不说话时，你可以主动聊一句；
> 两次至少间隔 30 分钟，连续两次没人回就暂停，晚上 23 点到早上 8 点别打扰。

模型应调用 `assist_idle_start`，返回 `enabled: true` 才代表成功。
配置参数可直接使用 [idle-settings.json](../examples/idle-settings.json)。
参数是工具输入，不是放入角色 JSON 的新字段。

| 参数 | 默认 | 范围 |
|---|---:|---|
| idleMinutes | 15 | 整数 1–1440，空闲等待时间 |
| cooldownMinutes | 30 | 整数 1–1440，两次主动触发的最短间隔 |
| maxUnanswered | 2 | 整数 1–5，连续无人回应时的触发上限 |
| quietStart | 23 | 0–23，安静时段起始小时，包含边界 |
| quietEnd | 8 | 0–23，结束小时，不包含边界 |

安静时段使用 **Harness 后端进程所在机器的本地时区**，状态中的 timeZone
用于核对。起止相等表示关闭安静时段；支持跨午夜。更改系统时区会影响它。
实际检查周期为 15 秒，因此到期后可能稍晚触发。

问“查看主动聊天状态”使用 `assist_idle_status`。
说“关闭主动聊天”使用 `assist_idle_stop`。查询和关闭只作用于当前会话。
更新设置时明确要求重新调用 start；它以当前时间重新计时并重置次数。

## 触发与暂停

- 从启用、用户新消息以及模型完成回复重新计算空闲等待。
- 只有 source.kind=user 的真正用户输入重置无人回应次数。
  插件自己发出的触发消息不会被当成人类回应。
- 会话忙碌、还有排队输入、处于安静时段时不触发，也不消耗次数。
- 达到 maxUnanswered 后暂停；用户再次发消息会恢复等待。
- 角色与记忆通过已有的提示词装配读取，不复制一套独立聊天记录。
- 每次触发只提交一个正常模型回合，不补发睡眠期间所有错过的次数。
- 提交失败会禁用该订阅并在状态中给出简短错误；明确重新启用才重试。
  已提交但模型失败的回合仍占一次额度，此处额度指触发次数，不是 token。

同时最多启用 200 个 live 会话。重名但被重新创建的 agent 不继承旧订阅。
子代理无法启用。主动触发回合不能调用 start 来自行重置次数。

## 关闭与运行条件

这是插件内部计时器，不是系统计划任务。**应用后端必须保持运行**；
窗口是否可最小化到后台取决于桌面端设置。关闭后端、睡眠、关机期间不会聊天。
会话被卸载、插件被卸载或应用重启后，订阅不保留，需在目标会话重新启用。
记忆仍按原机制持久保存，计时订阅与私人记忆不混在一起。

stop 和插件卸载撤销将来的触发；已经提交给宿主的回合可能继续完成。
要终止当前生成，使用宿主停止按钮；该按钮不等于关闭此订阅。
插件不会取消用户其他任务。

每次主动聊天会调用所选模型并产生正常的 token/服务用量，仍遵守宿主审批。
插件来源会保留在会话记录中，不伪装成用户真正发来的消息。
不包含 QQ、微信、X 推送，也不保证操作系统通知一定弹出。

## 离线验证与实机验收

`npm test` 使用注入时钟和模拟 agent，验证计时器确实调用 followup，
同时覆盖冷却、上限、夜间、用户恢复、取消和资源清理。无需模型账号。

实机验收需用户自行安装插件后，在测试会话中启用以下参数：
`{"idleMinutes":1,"cooldownMinutes":1,"maxUnanswered":1,"quietStart":0,"quietEnd":0}`。
等回复完成后不输入，约 1 分钟至 1 分 15 秒应触发一次模型回合，实际回复时间取决于模型速度；
继续等待不应出现第二次。发一条真实消息，等回复后再次验证；
最后调用 stop，确认不再触发。重启后 status 应报告未启用。

已在 Windows 官方桌面端验证安装和组件运行；尚未调用真实模型验证主动聊天。
